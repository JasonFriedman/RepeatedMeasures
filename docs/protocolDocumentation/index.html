Structure of a protocol

A protocol has a setup section, which lists the recording devices and the resources used in the experiment (images, sounds, beeps, targets, ...), a list of trials, and optionally a common section with trial options that are the same in every trial. In a generateProtocol.m file this looks like:

experimentDescription.setup.tablet.maxx = 48767;        % a recording device
experimentDescription.setup.tablet.maxy = 30479;
experimentDescription.setup.images = {'target.png'};    % setup options
experimentDescription.common.starttrial = 'keyboard';   % the same in every trial

experimentDescription.trial{1}.stimulus.showImage.stimuli = 1;
experimentDescription.trial{1}.targetType = 'keyboard';
experimentDescription.trial{1}.recordingTime = 5;
experimentDescription.trial{1}.filename = 'trial1';

tree = struct2xml(experimentDescription);
save(tree,'protocols/subject1.xml');

The protocol builder writes these files for you and checks the options as they are set. In MATLAB, protocolOptions('name') shows the same information as these pages.

Add a device to the setup section under its name, e.g. setup.tablet. At least one device is needed.

characterThis is a client to connect to a character server (over TCP/IP)

Responses

Set with trial{n}.targetType. The default is dummy (no response).

buttonPressThe response is pressing a button, using a button box connected to a DAQ card
colorInImageThe target(s) are defined by a color in an image
defineTargetThis response is to define a target for use later (e.g. with the response targetInSpace).
dummyThe dummy response does not record any response
fingerOppositionSequenceThe response is touching the thumb and another finger in a sequence N times
imageStateThe target is a state (using images stimuli)
keyboardThis response is pressing a key on the keyboard
keyboardsequenceThe response is pressing a certain sequence of keys N times
mouseEntersBoxThe response is moving the mouse into one of the specified boxes (which can be invisible)
movementThresholdThis response is moving past a certain location
pointToPointThis response is for (possibly repeated) point to point measurements.
showdataThis response does not stop the trial, but shows feedback (similar to showPosition).
stoppedMovingThis response is to stop a trial after the subject has stopped moving for a certain amount of time.
targetInSpaceThe target(s) are locations in space
targetOnScreenResponse of touching a target (e.g. on a touchscreen)
triggerThe trial ends when an external trigger is received

Trial starts

Set with trial{n}.starttrial. The default is dontWait.

buttonThe trial starts when a button is pressed, using a button box connected to a DAQ card. To use this, setup.MCtrigger should be set to 1 (for input), or there should be a DAQ device defined as a response device
colorInImageThe start position are defined by a color in an image
dontWaitStart the trial immediately
keyboardThe trial is started by pressing a key
mouseClickThe trial starts when the mouse button is clicked, optionally in a (possibly invisible) box
mouseInBoxThe trial starts when the mouse enters (or is already in) a (potentially invisible) box
pedalStart the trial by pressing a pedal
stylusButtonStart the trial when the tablet stylus button is pressed
targetInSpaceThe target(s) are locations in space
triggerThe trial starts when an external trigger is received
